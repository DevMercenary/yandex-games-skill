## 1. Установка и добавление в проект

1. Скачать последнюю версию `.c3addon` из GitHub: https://github.com/yandex-games-plugins/construct3/tags (релизы: https://github.com/yandex-games-plugins/construct3/releases).
2. Construct 3 → **Menu** → **View** → **Addon manager** (Менеджер дополнений).
3. **Install new addon…** (Установка нового дополнения) → выбрать скачанный `.c3addon`.

Добавить в проект:
1. ПКМ по макету → **Insert new object** (Вставить новый объект).
2. Раздел **Platform specific** («Платформы и API») → **YandexGamesSDK** → **Insert**.

После этого объект `YandexGamesSDK` доступен в листах событий и как `YandexGamesSDK.<выражение>`.

Возможности плагина: визуальные блоки для всего API Яндекс Игр; использование SDK в блоках JavaScript; локализация текста и спрайтов; вспомогательные условия (throttle/debounce), эмулятор ТВ-пульта.

## 3. Реклама

Порядок: изучить рекомендации по размещению (https://yandex.ru/dev/games/doc/sdk-adv.md#recommendations) → настроить вызовы в SDK → подключить монетизацию в Консоли (https://yandex.ru/dev/games/console/adv-monetization.md#enable-int-monetization).

### Полноэкранная реклама
- Действие **Показать полноэкранную рекламу**.
- Типичные места: `Система → Загрузочный макет выполнен` (показ на старте), функция выхода в меню.

### Видеореклама с вознаграждением
- Действие **Показать рекламу с вознаграждением** `(ID)`. **ID** — произвольная строка, чтобы различать вызовы рекламы в триггерах; с Рекламной сетью Яндекса не связана, можно оставить пустой.
- Триггеры:
  - **Вознаграждающая реклама `<ID>` просмотрена** — здесь выдавать награду.
  - **При ошибке любой вознаграждающей рекламы**.
  - **Любая вознаграждающая реклама открылась** / **Любая вознаграждающая реклама закрыта**.

Пример (из документации): глобальная константа `Реклама_X2Монеты = "x2coins-rewarded"`; кнопка `При нажатии` → `Показать рекламу с вознаграждением Реклама_X2Монеты`; `Вознаграждающая реклама Реклама_X2Монеты просмотрена` → `Вызвать Добавить монет (10)`.

Выключение звука на время рекламы (требование платформы):

| Триггер YandexGamesSDK | Действие Audio |
|---|---|
| Любая вознаграждающая реклама открылась | Установить тихий (Set silent) |
| Любая вознаграждающая реклама закрыта | Установить не тихий |
| При ошибке любой вознаграждающей рекламы | Установить не тихий |

### Стики-баннер
- Подключение в Консоли: https://yandex.ru/dev/games/sdk/sdk-adv.md#banner-on
- По умолчанию баннер показывается с запуска игры всю сессию.
- Чтобы управлять показом: в Консоли в блоке **Sticky-баннеры** включить **Использовать API для показа sticky-баннера**, затем использовать действия **Показать sticky-баннер** / **Скрыть sticky-баннер** (например, показывать в паузе/меню, скрывать в геймплее).

## 4. Авторизация и данные игрока

### Информация об игроке
- Действие **Запросить информацию об игроке** (параметр **Персональные данные**: `True/False` — запрашивать ли доступ к персональным данным).
- Триггеры **Информация об игроке загружена** / **Ошибка загрузки информации об игроке**.
- Условия:
  - **Игрок авторизован** — авторизован ли в Яндексе.
  - **Игрок предоставил доступ к персональным данным**.
- Выражения:

| Выражение | Тип | Описание |
|---|---|---|
| Signature игрока | `string` | Данные пользователя из профиля Яндекса и подпись: две строки в Base64 |
| Аватар игрока | `string` | Ссылка на аватар |
| Имя игрока | `string` | Имя игрока |
| Статус платящего игрока | `string` | Статус платёжной активности на платформе |
| Уникальный идентификатор игрока | `string` | Уникальный ID игрока |

Пример: `Система → Выполнить единожды` → `Запросить информацию об игроке (Персональные данные: False)`; `Игрок предоставил доступ к персональным данным` → `Установить username = YandexGamesSDK.Имя игрока`; `Ошибка загрузки информации об игроке` → `username = "Анонимный пользователь"`.

### Внутриигровые данные (облачные сохранения)
Работают через объект **JSON** Construct 3:

| Действие | Что делает |
|---|---|
| **Получить данные игрока** (ключи, JSON-объект) | Запрашивает данные пользователя и записывает в объект JSON. Пустая строка ключей = все данные |
| **Сохранить данные игрока** (JSON-объект, Flush) | Отправляет данные из объекта JSON в Яндекс Игры. `Flush: True` — отправить немедленно |
| **Получить численные данные игрока** | Запрашивает stats в объект JSON |
| **Сохранить численные данные игрока** | Отправляет stats из объекта JSON |
| **Увеличить численные данные игрока** | Инкремент численных значений |

Все эти действия **асинхронные** — после них ставьте `Система → Дождаться завершения предыдущих действий` (Wait for previous actions to complete), прежде чем читать результат.

Пример: функция `Загрузить игру` → `Получить данные игрока из ключей "" в PlayerDataJSON` → `Дождаться завершения предыдущих действий` → `ПрогрессИгры = int(PlayerDataJSON.Получить("levelprogress"))`. Функция `Сохранить игру` → `PlayerDataJSON: Установить для ключа "levelprogress" значение ПрогрессИгры` → `Сохранить данные игрока используя PlayerDataJSON, Flush: True`.

## 5. Удалённая конфигурация (флаги)

- Действие **Запросить удалённую конфигурацию** + триггеры **Удалённая конфигурация загружена** / **Ошибка загрузки удалённой конфигурации**. Запрашивать **один раз на старте игры**.
- Выражение **Флаг** `("ключ")` — значение флага.
- **Задать стандартное значение ключа** `("ключ", "значение")` — локальная конфигурация по умолчанию; всегда задавайте её на случай, если сервер недоступен (нет сети).
- **Задать особенность клиента** `("ключ", "значение")` — клиентские параметры, передаются при запросе конфигурации (для таргетинга/экспериментов).

Порядок в примере: `Загрузочный макет выполнен` → `Задать ключу "someProp" стандартное значение "someValue"` → `Задать особенность клиента "featureKey" значение "featureValue"` → `Запросить удалённую конфигурацию`; `Удалённая конфигурация загружена` → `someProp = YandexGamesSDK.Флаг("someKey")`.

## 6. Лидерборды

Предварительно создать лидерборд в Консоли: https://yandex.ru/dev/games/concepts/leaderboards.md#create. Если лидерборда с таким **Техническим названием** нет — запросы возвращают **404**.

### Отправка счёта
Только для **авторизованных** пользователей: сначала `Запросить информацию об игроке`, в `Информация об игроке загружена` проверить условие `Игрок авторизован` и выставить флаг `authorized`.

Действие **Отправить счёт в лидерборд**:

| Параметр | Тип | Описание |
|---|---|---|
| Название | `string` | Техническое название лидерборда |
| Счёт | `number` | Счёт игрока |
| Дополнительные данные | `string` | Необязательные метаданные |

Лимит: **не чаще 1 раза в 1 секунду**, иначе ошибка. Рекомендуется связка с отложенным событием: `При нажатии` → `Отложить событие "setScore" на 1 секунду`; `На отложенное событие "setScore"` + `authorized = true` → `Отправить счёт 10 в "score" с данными ""`.

### Получение записей
Действие **Запросить таблицу лидеров** + триггеры **При успешной загрузке таблицы лидеров** / **При ошибке загрузки таблицы лидеров** (все с одинаковыми параметрами):

| Параметр | Тип | Описание |
|---|---|---|
| Название | `string` | Техническое название лидерборда |
| Позиции из топа | `number` | Сколько записей из топа |
| Запросить позицию игрока | `boolean` | Включать ли позицию пользователя |
| Позиций вокруг игрока | `number` | Сколько записей выше и ниже пользователя |

После успешной загрузки использовать цикл **Для каждого игрока в текущей таблице лидеров** (внутри функции/триггера, не каждый тик; показывать индикатор загрузки). Внутри цикла доступны выражения группы **Таблицы лидеров**:

| Выражение | Описание |
|---|---|
| Имя текущего игрока в таблице лидеров | `string`; `""`, если нет доступа к имени |
| Уникальный идентификатор текущего игрока в таблице лидеров | `string` |
| Позиция текущего игрока в таблице лидеров | Ранг по сравнению счёта всех игроков |
| Счёт текущего игрока в таблице лидеров | Счёт |
| Дополнительные данные текущего игрока из таблицы лидеров | Метаданные, отправленные со счётом |
| Аватар / Маленький / Средний / Большой аватар текущего игрока | `string` ссылки; `""`, если нет доступа |
| Индекс запрошенного интервала в таблице лидеров | Номер интервала (top / around могут дать несколько интервалов) |
| Название таблицы лидеров | Локализованное название |
| Техническое название таблицы лидеров | Не для показа пользователю |
| Тип таблицы лидеров | `numeric` (число) или `time` (секунды) |
| Смещение десятичной точки таблицы лидеров | `decimal_offset`: при `2` число `1234` показывается как `12.34` |

## 7. Инап-покупки

Порядок: подключить покупки заранее (https://yandex.ru/dev/games/doc/sdk-purchases.md#conditions) → добавить товары в Консоли (https://yandex.ru/dev/games/console/purchases.md#add-purchases) → настроить в SDK → протестировать (https://yandex.ru/dev/games/console/purchases.md#test).

### Процесс покупки
Действие **Инициализировать покупку**:

| Параметр | Тип | Описание |
|---|---|---|
| ID | `string` | Идентификатор товара в каталоге |
| Payload | `string` | Необязательные данные, отправляемые с покупкой |

Триггеры: **Успех покупки определённого товара** `(ID)`, **Успех любой покупки**, **Ошибка покупки определённого товара**, **Ошибка любой покупки** (игрок закрыл окно, не купив). В триггерах успеха доступно выражение **Токен покупки** (`YandexGamesSDK.Токен покупки`).

### Обработка покупок
- **Запросить покупки** → триггер **Покупки загружены** → цикл **Для каждой покупки**; внутри — выражения группы **Покупки** с постфиксом **в списке покупок** (например, **Идентификатор текущего товара в списке покупок**, **Токен текущей покупки в списке покупок**).
- **Поглотить покупку** `(токен)` — consume для расходуемых покупок.

Постоянная покупка (например, `DISABLE_ADS`):
- `Успешная покупка "DISABLE_ADS_PURCHASE"` → `DISABLE_ADS = True`.
- На старте: `Загрузочный макет выполнен` → `Запросить покупки`; `Покупки загружены` → `Для каждой покупки` → если `Идентификатор текущего товара в списке покупок = "DISABLE_ADS"` → `DISABLE_ADS = True`. Поглощать не нужно.

Используемая покупка (например, `BUY_10_COINS`):
- `Успешная покупка "BUY_10_COINS"` → `Поглотить покупку YandexGamesSDK.Токен покупки` → `Дождаться завершения предыдущих действий` → `Добавить 10 в coins`.
- На старте (на случай, если поглощение прервалось): `Запросить покупки` → `Для каждой покупки` → если ID = `"BUY_10_COINS"` → `Поглотить покупку YandexGamesSDK.Токен текущей покупки в списке покупок` → `Дождаться…` → `Добавить 10 в coins`.

### Каталог товаров
**Запросить каталог товаров** → **Каталог товаров загружен** / **Ошибка загрузки каталога товаров** → цикл **Для каждого товара в каталоге**; внутри — выражения группы **Покупки** с постфиксом **в каталоге**.

## 8. Асинхронный мультиплеер

Основная статья (HTML5): https://yandex.ru/dev/games/doc/sdk-multiplayer-sessions.md

### Инициализация
Действие **Проинициализировать мультиплеер** (стартовая инициализация + загрузка сессий оппонентов):

| Параметр | Тип | Описание |
|---|---|---|
| Количество сессий | `number` | Сколько сессий загрузить (не более 10) |
| Время хода | `number` | Максимальное время хода оппонента, мс |
| Метаданные | `JSON` | Объект для выборки сессий |

Параметры подробно: https://yandex.ru/dev/games/doc/sdk-multiplayer-sessions.md#init

Триггер **Мультиплеер инициализирован** → цикл **Для каждого оппонента**, выражения:
- **Данные игрока текущей сессии** (по ключу `avatar` или `name`);
- **Идентификатор текущей сессии в списке сессий**.
Действие **Получить метаданные текущей сессии** (в JSON-объект).

### Запись сессии
- **Записать транзакцию** (JSON-объект с данными).
- **Сохранить сессию** (JSON-объект с метаданными).
Подробнее: https://yandex.ru/dev/games/doc/sdk-multiplayer-sessions.md#record

### Воспроизведение сессий оппонентов
Только через события:
- Триггер **Сессионные транзакции получены**: выражение **Идентификатор сессии в событии сессионной транзакции**; цикл **Для каждой транзакции** с выражениями **Идентификатор текущей транзакции в списке транзакций**, **Время текущей транзакции в списке транзакций**; действие **Получить данные текущей транзакции** (в JSON).
- Триггер **Сессия окончена**: выражение **Идентификатор сессии в событии окончания**.
- **Отметить начало геймплея** — запускает отправку сессий в обработчики; **Отметить конец геймплея** — приостанавливает.

Пример из документации: `start: При нажатии` → `InitMeta: Парсинг JSON "{""meta1"":{""min"":7,""max"":9}}"` → `Инициализация мультиплеера (сессий: 1, время хода: 20000 мс, мета: InitMeta)` → `Дождаться…` → `Отметить начало геймплея`. `commit: При нажатии` → `hp -= 1` → `transaction: Парсинг JSON "{""data"":"&hp&"}"` → `Записать транзакцию transaction`. `end: При нажатии` → `pushMeta: Парсинг "{""meta1"":8}"` → `Сохранить сессию с метаданными pushMeta`.

## 9. Поддержка ТВ

Требования к ТВ: пункт 1.6.3 — https://yandex.ru/dev/games/requirements/1/6/3.md

### Пульт
- Условие **Нажата кнопка ТВ-пульта** — истинно, пока кнопка удерживается (использовать в `Каждый тик`).
- Триггер **При нажатии кнопки ТВ-пульта**, триггер **При отпускании кнопки ТВ-пульта**.
- Кнопки: **Вверх**, **Вниз**, **Влево**, **Вправо**, **OK**.

### События `HISTORY_BACK` и `EXIT`
`HISTORY_BACK` вызывается кнопкой **Back** пульта, голосовой командой или жестом. Ожидаемое поведение:
- в стартовом меню — окно подтверждения выхода;
- во время игры — пауза и игровое меню;
- двойное нажатие во время игры — окно подтверждения выхода.

Плагин: условие **При событии HISTORY_BACK**; выход из игры — действие **Отправить событие** с параметром `EXIT`.

Пример: `При событии HISTORY_BACK` → переключить `МенюВыходаОткрыто`; `Нажата кнопка OK на ТВ пульте` + `МенюВыходаОткрыто = true` → `Отправить событие EXIT`.

### Эмулятор пульта
Встроен в плагин, включается клавишей **F6**. Работает **только в режиме превью**, в релизе отсутствует.

## 10. Throttle и Debounce

Особые условия плагина:

| Условие | Поведение |
|---|---|
| **Не чаще чем раз в `<X>` секунд** (throttle) | Ограничивает частоту выполнения ветки. Для кода по действию игрока, когда таймер неприменим. Не использовать в `Каждый тик` — для этого есть `Каждые <X> секунд` |
| **Отложить событие** `("имя", секунды)` + триггер **На отложенное событие** `("имя")` (debounce) | Аналог `Сигнал → При получении сигнала`, но вызов откладывается на X секунд с момента **последней** попытки. Для методов SDK с лимитами (например, счёт в лидерборд — 1 раз/сек) |

Разница: throttle ограничивает частоту, debounce откладывает вызов до затишья. Статьи: https://doka.guide/js/debounce/, https://doka.guide/js/throttle/. Несоблюдение лимитов SDK может привести к отказу в модерации.

## 11. Яндекс Метрика

1. Указать **ID счётчика в Метрике** в свойствах плагина (https://metrika.yandex.ru).
2. Действие **Отправить цель**:

| Параметр | Тип | Описание |
|---|---|---|
| Название цели | `string` | Название цели в Метрике |
| Дополнительные данные цели | `JSON` | Необязательные данные |

Пример: `Кнопка → При нажатии` → `Отправить цель "promo_banner_click" в Яндекс Метрику`.

## 12. Локализация текста

Автоматическая система перевода; в большинстве случаев кода не требуется.

1. В папке проекта **Files** создать подпапку **`i18n`**.
2. Внутри создать JSON-файлы с именами по кодам языков ISO 639-1: `en.json`, `ru.json`, … (список языков платформы: https://yandex.ru/dev/games/concepts/languages-and-domains.md).

`en.json`:

```json
{
    "game": { "title": "First Fantasy 10" },
    "potions": { "health": "Health Potion", "mana": "Mana Potion" }
}
```

`ru.json`:

```json
{
    "game": { "title": "Первая Фантазия 10" },
    "potions": { "health": "Зелье жизни", "mana": "Зелье маны" }
}
```

Использование:
- В макете: текст объекта `{game.title}` → в превью/игре подставляется перевод по языку игрока.
- В событиях: `Text → Установить текст "{potions.mana} = 10$"` → `Mana Potion = 10$`; работает при любом изменении текста в рантайме (в т. ч. `Typewriter text`).
- Заменяются ключи внутри объектов **Text**, **Sprite Font** и **AdaptiveText**.
- Язык по умолчанию — свойство плагина «Стандартный язык перевода».

## 13. Локализация спрайтов

Нужны файлы переводов для всех нужных языков (раздел 12).

1. Создать спрайт.
2. Добавить анимации с именами-кодами языков (`en`, `ru`, `tr`, `ar`, `hi`, …).
3. В каждую анимацию положить соответствующую графику.
4. В превью/игре плагин переключит спрайт на анимацию текущего языка.

Внимание: если в спрайте есть анимация с именем, не являющимся допустимым кодом языка, плагин **пропустит весь спрайт** при локализации.

## 14. Плагин AdaptiveText

Отдельный плагин **AdaptiveText** — текст, подстраивающий кегль под заданные границы (длинные ники игроков из лидербордов, удлинившиеся после перевода строки). Скачать: https://github.com/yandex-games-plugins/construct3/releases. Поддерживает подстановку `{ключ}` локализации.

## 15. Подводные камни

- Все действия SDK (данные игрока, покупки, лидерборды, мультиплеер) асинхронные: ставьте `Дождаться завершения предыдущих действий` перед чтением результата.
- Лидерборд: 404, если техническое название не совпадает с Консолью; счёт — только авторизованным; не чаще 1 раза/сек → используйте «Отложить событие».
- Циклы `Для каждого игрока в таблице лидеров` / `Для каждой покупки` / `Для каждого товара в каталоге` — только внутри триггера загрузки или функции, не каждый тик.
- Расходуемые покупки: поглощать токеном и перепроверять список покупок на старте; постоянные — не поглощать.
- Rewarded ID — строка для своих триггеров, не ID блока РСЯ.
- Стики-баннер по умолчанию показывается всегда; ручное управление требует включения опции в Консоли.
- Эмулятор пульта (F6) — только превью.
- Лишняя анимация в локализованном спрайте отключает его локализацию.
- Всегда задавайте локальные значения флагов до запроса Remote Config.
