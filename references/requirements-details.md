## Debug-панель

Многие пункты (1.13, 1.19, 2.14, 8.4.1) модерация проверяет через debug-панель. Как открыть:

- **Через Консоль разработчика**: Консоль Яндекс Игр → выбрать игру → кнопка **Открыть с debug-панелью** (левый верхний угол).
- **Через адресную строку**: добавить параметр `debug-mode=16` к URL игры, например `https://yandex.ru/games/app/XXXX?debug-mode=16`, где `XXXX` — ID игры.

На панели есть кнопка **SDK mocks** ⚒️ с моками (валюта, язык, ссылки на игры), индикатор Game Ready, индикатор геймплея 🎮, индикатор I18N 文, маркер лоадера `IF`/`IT`. Перед проверкой языка и ссылок модерация очищает кеш браузера. После включения мока нужно подождать 5 секунд и перезагрузить игру.

## 1.2 Авторизация

**Суть**: регистрация/авторизация на сторонних сервисах запрещена. Допустима только авторизация с Яндекс ID через SDK (`ysdk.auth.openAuthDialog()` — см. sdk-player). Игра должна полноценно работать без авторизации.

Правила, если авторизация добавлена:

- Пользователь может играть без регистрации и авторизации (гостевой вход), прогресс при этом сохраняется.
- Авторизация — только Яндекс ID, только через SDK.
- Предложение авторизоваться содержит пояснение преимуществ: сохранение прогресса в облаке; уведомления о новинках и акциях; инап-покупки доступны в любом браузере, а не только в текущем.
- Нет предложений авторизации на сторонних сервисах.
- После входа в аккаунт предложение авторизации больше не показывается.

**1.2.1 Осознанное действие**: переход на страницу авторизации только по нажатию элемента, из вида которого понятно, что он ведёт к авторизации (например, кнопка «Авторизоваться»). Пользователь может отказаться и продолжить играть.

| Правильно | Неправильно |
|---|---|
| Основные функции доступны без авторизации. | В игру можно зайти/играть только после авторизации. |
| Предложение авторизоваться ведёт на Яндекс ID. | Предложение авторизации на сторонних сервисах. |
| Можно отказаться и продолжить играть. | Нельзя отказаться, или предложение настойчиво и часто показывается. |
| После входа предложение больше не появляется. | После входа предложение продолжает показываться. |
| Переход к авторизации по элементу, явно обозначающему авторизацию. | Страница авторизации открывается по кнопкам **Лидерборд** или **Оценить игру**. |
| В окне авторизации перечислены преимущества входа. | В окне нет информации о преимуществах. |

**Типичные отказы**: гейт на старте «войдите, чтобы играть»; скрытый вызов диалога авторизации из кнопки лидерборда/оценки; повторные всплывашки авторизации после входа.

## 1.3 Звук вне игры

**Суть**: при потере фокуса звук из игры останавливается.

**Реализация**: подписаться на события SDK `game_api_pause` и `game_api_resume` (sdk-events, раздел pause-resume). Платформа отправляет их, когда нужно поставить игру на паузу или возобновить.

1. На `game_api_pause` — выключить звук и поставить геймплей на паузу.
2. На `game_api_resume` — возобновить звук и игру.

Подписка — через `ysdk.on('game_api_pause', cb)` / `ysdk.on('game_api_resume', cb)`, отписка — `ysdk.off(...)` (см. 1.19.4: логика обработки должна соответствовать документации).

**Методика проверки** — звук должен останавливаться во всех трёх случаях:

1. Сворачивание окна браузера (ПК) или приложения (телефон).
2. Переключение на другую вкладку в том же окне.
3. Открытие меню выбора вкладок в мобильном браузере.

**Не считается нарушением**:

- Звук останавливается не сразу, а в течение **2 секунд** после ухода с вкладки.
- Звук не останавливается после клика по баннеру рекламы и перехода на вкладку рекламодателя.
- На iOS в меню выбора вкладок звук продолжает играть.

**Типичный отказ**: музыка/эффекты продолжают играть после сворачивания окна или смены вкладки (особенно фоновая музыка, запущенная через `<audio loop>` без обработки паузы).

## 1.6.1.6 / 1.6.2.5 Системный плеер

**Суть**: ни в каких браузерах не отображается системный медиаплеер браузера/ОС, вызванный игрой (панель «управление музыкой/видео» в Chrome/Яндекс Браузере, плеер в шторке уведомлений на телефоне).

**Причина**: браузер регистрирует медиасессию, когда воспроизведение идёт через HTML-элементы `<audio>` или `<video>`.

**Решение**: использовать **Web Audio API** — он работает напрямую с аудиоконтекстом и не регистрирует медиасессию. Типовой сценарий:

1. Создать контекст: `const ctx = new AudioContext()`.
2. Загрузить файл через `fetch()` и декодировать `ctx.decodeAudioData()`.
3. Создать источник `AudioBufferSourceNode` и подключить к выходу: `source.connect(ctx.destination)`.
4. Запустить: `source.start()`.

**Проверка на мобильных**: запустить игру, провести вниз для открытия панели уведомлений. Допустимо: плеера нет; плеер есть, но вызван звуком из другой вкладки/приложения.

**Проверка на десктопе**: включить системный плеер в настройках браузера (Яндекс Браузер: меню → **Настройки** → **Интерфейс** → **Общее** → «Показывать на панели инструментов кнопку управления музыкой и видео»), убедиться, что плеер работает на каком-нибудь видео, затем открыть игру. Допустимо: плеера нет; плеер есть, но при клике по значку видно, что он вызван другой вкладкой.

**Типичный отказ**: фоновая музыка через `<audio>`/`new Audio()` (в т.ч. в движках, где это дефолт) — в шторке телефона появляется плеер с названием вкладки.

## 1.6.3 Адаптация для ТВ

Требования для платформы ТВ:

1. Игра занимает всю площадь экрана, доступен полноэкранный режим.
2. Управление стрелками ТВ-пульта; стрелок достаточно для полного прохождения.
3. Обрабатываются кнопки **Back** и **OK** пульта.
4. Отсутствуют инап-покупки.
5. Нет ссылок на другие игры разработчика.

**События клавиш** (`KeyboardEvent.key`):

- Стрелки: `ArrowLeft`, `ArrowUp`, `ArrowRight`, `ArrowDown`.
- **OK**: `Enter`.

Пульт генерирует **одно событие в момент времени** — одновременных нажатий нет. Если геймплей требует нескольких клавиш сразу, сделать часть действий автоматическими (прыжок, движение вперёд).

Кнопки пульта должны работать и в игре, и в: стартовом меню (запуск по **OK**, выбор уровня стрелками); внутриигровом меню, вызываемом по **Back**.

Для движков с поддержкой геймпада ТВ-пульт регистрируется как геймпад — настроить стрелки и **OK** через API геймпада (Unity KeyCode, Construct Gamepad plugin, Defold input gamepads).

**Кнопка Back** (есть на всех Smart TV):

- В стартовом меню — окно подтверждения выхода из игры.
- Во время игры: однократно — пауза и игровое меню; дважды — окно подтверждения выхода.

**Определение ТВ через SDK**: после инициализации `ysdk.deviceInfo.type` возвращает тип устройства; на телевизоре — строка `'tv'`. По этому признаку включать логику управления пультом, тексты обучения и т.д. (В SDK также есть флаг `ysdk.deviceInfo.isTV()`.)

**Публикация**: в черновике игры в Консоли отметить платформу **ТВ**. После модерации игра попадает в бандл ТВ (`https://yandex.ru/games/?bundle=tv`).

**Тестирование на ТВ с магазином Яндекс ТВ**: открыть приложение Яндекс Игр, дождаться стартовой страницы, выбрать левый верхний элемент интерфейса, набрать на пульте ← ↑ ← ↑ ← ↑ ← ↑ — откроется поле ввода ID игры (черновика).

## 1.9 Сохранение прогресса

**Суть**: в играх с прогрессом (уровни, рекорды, достижения, улучшения) изменения сохраняются **сразу после действия игрока** или **по специальной кнопке**. После обновления страницы или смены ориентации экрана прогресс не теряется. Любая другая механика сохранения (например, периодическая) должна быть описана в поле **Комментарий разработчика** черновика — иначе отказ.

### Где сохранять

| Хранилище | Когда | Замечания |
|---|---|---|
| **Серверы Яндекс Игр** (`player.setData` / `player.getData`, см. sdk-player ingame-data) | Рекомендуется для большинства игр | Ускоряет загрузку, поддержка игроков на стороне Яндекса. Если поддерживаются облачные сохранения — отметить это в черновике (пункт 1.11). |
| **Внешний сервер** | Сложные проекты с инфраструктурой | Своя система хранения и синхронизации; хостинг и поддержка на разработчике. |
| **Браузерные хранилища** (localStorage, IndexedDB) | Только простые игры **без инап-покупок** | Прогресс часто теряется (смена устройства/браузера, очистка кеша), поддержка не восстановит. |

Облачные сохранения **обязательны** для игр с инап-покупками (1.13.3) и позволяют продолжать на разных устройствах.

### Когда сохранять обязательно

| Нужно сохранение | Сохранение необязательно |
|---|---|
| Новый уровень открывается после прохождения предыдущего. | Все уровни доступны сразу. |
| Можно поставить рекорд, получить достижение, выиграть. | Нет рекордов, достижений, возможности выиграть. |
| Сложность растёт по мере прохождения. | Сложность не зависит от прогресса. |
| Уровень может занять несколько игровых сессий. | Любой уровень проходится за одну сессию, все уровни доступны. |

Примеры без обязательного сохранения: простые раскраски, пазлы, викторины без прогресса.

### Механика

- Сохранять сразу после действия пользователя или по кнопке.
- Сохранять **независимо от того, авторизован пользователь или нет**.
- На мобильных — сохранять при смене ориентации; после поворота должно отображаться то же состояние.
- Проверка: обновление страницы в любой момент (после нажатия кнопки сохранения, если она есть) — прогресс тот же.

| Правильно | Неправильно |
|---|---|
| После обновления страницы рекорды/прогресс восстанавливаются. | Не восстанавливаются. |
| Сохранение сразу после действия или по кнопке. | Сохранение периодически (по таймеру) без описания в комментарии. |
| Сохранение в конце уровня или при получении достижения. | Игра вообще не сохраняет. |
| Прогресса нет — сохранения нет. | Прогресс есть, но не сохраняется. |
| При смене ориентации состояние сохраняется. | После поворота состояние сбрасывается. |
| Нестандартная механика описана в комментарии разработчика. | Нестандартная механика не описана. |
| Сохранение работает для каждого пользователя, авторизован он или нет. | Результаты сохраняются только в лидерборде. |

## 1.10 Корректное отображение

**Суть**: игра корректно отображается при изменении размера окна и повороте экрана:

1. Элементы не обрезаются и не выходят за рамки экрана.
2. Нет браузерной прокрутки страницы (системного скроллбара окна) и swipe-to-refresh. Собственная прокрутка контента внутри игры допустима.
3. Элементы и тексты не накладываются друг на друга.
4. Игрой можно управлять одной рукой; основной экран не требует прокрутки/смахиваний — всё видно сразу. Исключение: стратегии, RPG и другие жанры с большим полем, которое допустимо перемещать.

### Обрезка и наложение (1.10.1, 1.10.3)

Два условия выполнения: все важные элементы видны так, что их смысл понятен; всеми элементами удобно пользоваться.

**Нельзя перекрывать или обрезать**: кнопки; тексты; значимые элементы (игровые объекты, препятствия, шкалы, индикаторы); **предупреждения о рекламе**. Все они должны быть заметны и читаемы на всех заявленных платформах и разрешениях.

**Критичная обрезка** (отказ/снятие): из-за скрытой части элементом неудобно пользоваться, его плохо видно, тяжело понять значение, или обрезка влияет на кликабельность. Примеры из практики модерации:

- Обрезано игровое поле — взаимодействие невозможно.
- Счёт виден не полностью; баланс/таймер частично скрыты; кнопка вынесена за экран.
- Две трети кнопки за верхней границей — непонятно, за что она отвечает.
- Предупреждение «Реклама через 2» обрезано наполовину.
- Кнопки магазина обрезаны снизу — текст не читается, контент недоступен.
- Картинки викторины (основной контент) обрезаны на две трети.
- Текст визуальной новеллы обрезан (основной контент жанра).
- Сводка характеристик персонажа частично за экраном.

**Незначительная обрезка** (одобрение): элемент виден не полностью, но легко читается и им несложно пользоваться — края эмодзи-реакций, края форм ответов при полностью видимом тексте, кончик стрелки кнопки «Заново», надпись «Игра закончена» чуть срезана сверху.

**Критичное наложение** (отказ): перекрыта значительная площадь объекта, или это мешает читать/взаимодействовать. Примеры: кнопка перекрывает текст другой кнопки; карта пасьянса на 2/3 под счётчиком очков; значок рекламы на тексте кнопки; кнопка «Смотреть рекламу» полностью закрывает описание награды; текст на тексте; прозрачное окно магазина поверх игрового поля; кнопка «В меню» скрыта за персонажем.

**Незначительное наложение** (одобрение): кнопки уровней слегка пересекаются, но читаемы; текст кнопки чуть перекрыт объектом, но понятен; иллюстрации туториала частично под рекламой, тексты целы; иконка настроек чуть перекрыта; название игры и кнопка «Играть» немного пересекаются.

### Сценарии проверки адаптивности

- **Изменение размера доступной области** — растянуть/сузить по вертикали, горизонтали, диагонали; изменить масштаб на разных устройствах.
- **Вход в полноэкранный режим и выход** — все элементы на месте.
- **Показ/скрытие стики-баннеров** — элементы не обрезаются и не перекрываются.
- **Смена ориентации на мобильных** — элементы остаются в пределах экрана (если поддерживаются обе ориентации). Ориентацию можно зафиксировать в Консоли разработчика.

Методика ресайза на ПК (модерация использует PNG-разметку под разрешения 1280×1024, 1366×768, 1600×900, 1680×1050, 1920×1080, 1920×1200, 2560×1080, 2560×1440, 3840×2160; macOS 1680×1050, 2560×1600):

1. Вписать окно с игрой в зелёный прямоугольник (соотношение 16:9).
2. Ужать окно браузера на **20%** по отдельным осям (до красного прямоугольника).
3. Вписать окно в красный прямоугольник.

Если игра отображается некорректно при этих действиях — отказ. Мобильную версию без телефона проверяют через DevTools.

### Прокрутка и swipe-to-refresh (1.10.2)

Как отличить: **браузерная (системная)** прокрутка доступна из любого места игры — прокручивается само окно; **внутриигровая** прокручивает отдельный элемент/меню.

- На ПК проверяется при масштабе браузера **от 80% до 125%**. Скроллбар вне этого диапазона — не нарушение.
- На мобильных: скроллбар может появляться справа от стики-баннера после выхода из полноэкранного режима (особенно iOS Safari) — баннер не уменьшается. Во время загрузки прокрутка при смахивании допустима, но после полной загрузки она должна исчезнуть или оставаться только на стики-баннере. При отключённом стики-баннере скроллбара быть не должно.
- **Swipe-to-refresh** (страница перезагружается при свайпе сверху вниз) — нарушение, функция должна быть отключена.

Практика (не из документации Яндекса, типовое решение): `html, body { margin:0; height:100%; overflow:hidden; overscroll-behavior:none; touch-action:none; }`, канвас `100vw × 100vh` с пересчётом на `resize`/`orientationchange`.

## 1.12 Монетизация

**Суть**: по умолчанию в игре обязательно подключена монетизация — реклама или инап-покупки.

- **Реклама**: полноэкранные блоки, блоки с вознаграждением (rewarded) или стики-баннеры. **Не считается** стартовый рекламный блок, который платформа показывает во время загрузки игры.
- **Покупки**: на странице **Инап-покупки** в Консоли добавлены товары, на вкладке **Настройки** есть надпись **Покупки подключены**.

Если монетизация не нужна — явно написать об этом в поле **Комментарий разработчика** на вкладке **Черновик** в Консоли. Модерация одобрит, если выполнено хотя бы одно: есть реклама, есть покупки, или указано, что монетизация не предусмотрена.

При работе по единой лицензионной схеме (ЕЛС) монетизация подключена автоматически (статус — на странице payments, check-ulm).

## 1.13 Инап-покупки

Требования:

1. Подключён метод консумирования.
2. Портальная валюта определяется автоматически: название и иконка берутся из SDK.
3. Прогресс сохраняется на сервере и доступен одному пользователю с разных устройств.
4. Все покупки имеют стоимость цифрами и указание портальной валюты.
5. Описание покупки (изображение, название, состав, характеристики) соответствует тому, что получает пользователь.
6. Список покупок в игре соответствует Консоли: активные покупки на вкладке **Инап-покупки** есть в игре; если вкладка пуста или покупки неактивны — в игре их нет.

### 1.13.1 Консумирование

Если тестировать покупки до настройки консумирования, останутся необработанные платежи, которые сделают прохождение модерации невозможным. Проверка:

1. При необходимости добавить логин для тестовых покупок (Консоль → purchases → test).
2. Открыть игру, совершить покупку, дождаться модального окна.
3. **Не нажимая «Хорошо»** в модальном окне, обновить страницу.
4. Проверить, что покупка сохранилась (т.е. необработанная покупка была получена через `getPurchases()` и сконсумирована после перезагрузки).

### 1.13.2 Автоопределение портальной валюты

1. Получить каталог: `payments.getCatalog()`.
2. Для каждого товара брать название и иконку валюты из свойств `IProduct`:
   - `IProduct.price: string` — цена с кодом валюты.
   - `IProduct.priceCurrencyCode: string` — код валюты.
   - `IProduct.getPriceCurrencyImage(size: 'small' | 'medium' | 'svg'): string` — URL иконки валюты.

Проверка: открыть игру с debug-панелью → **SDK mocks** ⚒️ → иконка валюты 🪙 → **Currency mock is enabled** → подождать 5 секунд → перезагрузить игру. Текстовое обозначение валюты должно смениться на **TST**, иконка — на знак йены **¥**. Если не сменились — методы SDK не используются, отказ по 1.13.2. Захардкоженные «Яны»/иконки — отказ.

### 1.13.3 Сохранение покупок

Покупки с одного аккаунта хранятся на сервере (Яндекс Игр или внешнем) и доступны при смене устройства/браузера. Список купленного — через `getPurchases()`. Проверка (одна сессия, не держать несколько браузеров с игрой):

1. Совершить покупку, дождаться обработки, убедиться, что ценности появились.
2. Закрыть вкладку.
3. Зайти в игру на том же домене с другого устройства или в другом браузере, авторизоваться тем же логином.
4. Покупка и прогресс должны сохраниться.

### 1.13.5 Покупка соответствует предложению — отключение рекламы

1. Совершить покупку отключения рекламы, дождаться обработки.
2. Реклама внутри игры должна исчезнуть:
   - Если в названии/описании сказано, что отключается вся реклама — исчезают и полноэкранные блоки, и стики-баннеры.
   - Если конкретных указаний нет — отключается **вся** реклама.
3. **Не требуется** отключать: полноэкранный блок на старте (его принудительно показывает платформа); rewarded-блоки (их просмотр приносит бонусы).

Если после покупки показывается хотя бы один вид рекламы, не оговорённый в описании — отказ.

## 1.14 Технические ошибки

**Суть**: игра работает без ошибок, зависаний и вылетов при обычном геймплее и при: повороте экрана, длительном нажатии, жестах, сворачивании браузера, показе рекламы, переходах по истории браузера и т.п. Должна корректно загружаться, не зависать, не содержать технических надписей, не вызывать ошибок и браузерных уведомлений.

**Загрузка — причины отказа**: игра не загружается (видна только иконка или чёрный экран); ошибка в консоли браузера при загрузке; игра начинает загружаться только после клика по экрану; загрузка только после перезагрузки страницы; вылет при перезагрузке во время загрузки («повторно возникла проблема»); страница не загружается на iOS.

**Зависания**: игра перестаёт отвечать после перехода на другую вкладку и обратно; после рекламы экран загрузки висит и не реагирует; чёрный экран после выхода из полноэкранного режима; чёрный прямоугольник поверх поля при ресайзе.

**Зависания из-за рекламы**: после перехода по рекламе и возврата игра не реагирует на клики; после rewarded-рекламы и «Закрыть» — чёрный экран; таймер предупреждения о рекламе зацикливается (доходит до нуля и начинается снова, реклама не стартует).

**Технический текст** (отказ): всплывающие отладочные строки (`##(InputEventAction: action-start_game, pressed=(false)##`); отладочные меню (`Import Saves / Export Saves / Download Log / Powered by Ren'Py`); исходный код на экране загрузки; служебная информация (версия, service name, acc id, quality) в углу экрана.

**Уведомления об ошибках** (отказ):

- Браузерное `beforeunload`-уведомление «Уверены, что хотите закрыть эту страницу? Введённые данные могут не сохраниться» — не использовать.
- `alert()` с ошибками, например `TypeError: Cannot set properties of null (setting 'onclick')`.
- Ошибка превышения лимита запросов SDK: «Превышено количество запросов к /games/api/sdk/v1/player/data. Пожалуйста, пересмотрите использование методов SDK» / `Error: The number of requests is exceeded. Try again later.` — не дёргать `player.getData/setData` в цикле; сохранять по событию, дебаунсить.
- `An error occurred running the Unity content on this page ... RuntimeError: memory access out of bounds` — игра слишком тяжёлая для устройства.

## 1.15 Завершенный вид

**Суть**: игра завершена, не в разработке/тестировании; реализованы тексты, графика, управление, механики. Бета-версию пропустят только если контента хватает на **10 и более минут** и нет явных недоработок.

Причины отказа по категориям:

- **Тексты**: нечитаемые надписи (один символ вместо текста); битая кодировка (квадраты вместо букв); пустые рамки без текста.
- **Текстуры**: застревание персонажа в объектах; выпадение за пределы поля (движение по всей карте без ограничений, игнор финиша); при ресайзе или выходе из полноэкранного режима пропадают элементы (двери, платформы, собранные предметы) — уровень непроходим.
- **Управление**: не работает управление машиной/персонажем; выбранный объект (серая машина) не соответствует полученному (синяя).
- **Изображения**: битые иконки (стандартная иконка «изображение не загрузилось»).
- **Разработка**: враги не двигаются, урон не проходит; сцена выглядит как редактор; работает одна кнопка из двух, ползунок движется сам; персонаж ходит по одному пути без препятствий; после конца игры экран-тупик без кнопок (нет выхода в меню/рестарта); надписи «в разработке», «demo», «trial version»; текст нарисован от руки/заглушки.

## 1.19 Методы SDK

Требования:

1. SDK инициализируется строго по документации (актуальный лоадер).
2. Когда пользователь может приступить к игре, вызывается `LoadingAPI.ready()` (`ysdk.features.LoadingAPI?.ready()`).
3. Если есть разметка геймплея, `GameplayAPI.start()` / `GameplayAPI.stop()` (`ysdk.features.GameplayAPI?.start()` / `?.stop()`) вызываются в моменты, описанные в разделе «Геймплей».
4. Если используются `ysdk.on()` / `ysdk.off()` для `game_api_pause` / `game_api_resume`, логика соответствует разделу «Пауза и возобновление».

### 1.19.1 Актуальный лоадер

На debug-панели слева от индикатора Game Ready две буквы:

- `IF` (init false, подсказка _Is loader: false_) — старый лоадер. Не проходит.
- `IT` (init true, подсказка _Is loader: true_) — новый лоадер. Требуется.

### 1.19.2 Game Ready

Платформа сначала показывает свой загрузочный экран (пульсирующая иконка и «Загрузка»; его можно скрыть кликом). Модерация проверяет **загрузочный экран самой игры**: сторонние ссылки, чужие логотипы, элементы, нарушающие авторские права — отказ.

Проверка: индикатор Game Ready на debug-панели должен смениться с фиолетового на зелёный **в течение 90 секунд**; затем перезагрузка и повторная проверка момента смены цвета. Модерация смотрит, что индикатор меняется **когда игра становится доступна**, и что загрузочный экран не пропускается кликом.

`LoadingAPI.ready()` должен быть привязан к **реальной готовности игры**, а не к таймеру.

**Корректный момент вызова** — когда происходит любое из:

- Начинается взаимодействие: доступно управление (в т.ч. мини-игрой во время загрузки); открылось меню или «Нажмите, чтобы начать»; начался обратный отсчёт; началось обучение.
- Появилось всплывающее окно: политика конфиденциальности, лицензионное соглашение, предложение авторизоваться, ежедневный бонус — даже если фоновая загрузка ещё идёт.
- Начался неинтерактивный элемент: кат-сцена, диалог, стартовая анимация (облёт локации).
- Доступны настройки (графика, управление), создание/выбор персонажа, карты или уровня.

**Не подключён**:

- Индикатор стал красным через 90 секунд — подсказка `"ready" called on timeout` (SDK инициализирован, ready не вызван или вызван слишком поздно).
- Индикатор не меняет цвет и мигает фиолетовым — подсказка `SDK is not initialized. Wait for "unit" call` (SDK не инициализирован).

Типичная ошибка: игра уже показывает «Коснитесь, чтобы продолжить», пользователь играет, а `ready()` вызывается позже (или вообще на таймере).

### 1.19.3 Разметка геймплея

Индикатор 🎮 на debug-панели: зелёный — геймплей идёт (`start()` вызван), красный — геймплей на паузе (`stop()` вызван). Сценарии, которые проверяет модерация (индикатор должен переключаться в обе стороны):

- Запуск и завершение уровня.
- Открытие и закрытие игрового меню.
- Открытие и закрытие меню покупок.
- Запуск и закрытие рекламы.
- Потеря фокуса и возврат (другая вкладка, другое окно/программа) — отслеживать через `game_api_pause` / `game_api_resume`.

Некорректно: после конца уровня индикатор остаётся зелёным; при открытии меню остаётся зелёным; после закрытия рекламы остаётся красным; при уходе в другую программу остаётся зелёным.

Практическое правило: `stop()` перед `showFullscreenAdv`/`showRewardedVideo`, при открытии любого модального окна, при `game_api_pause`; `start()` при возврате в активный геймплей, при `game_api_resume` (если игра была в геймплее).

## 2.4 Игровые механики

**Суть**: игра соответствует **хотя бы одному** критерию:

- соревновательные механики;
- прогресс, зависящий от действий игрока (счёт, путешествие по миру, открытие локаций, продвижение по сюжету);
- цель («спасти принцессу», победить соперника, пройти все уровни);
- завершение (можно выиграть или проиграть).

**Проходят**: гонки с очками и рекордами; судоку (конечная цель); хоррор с сюжетом и локациями; кликер со счётом и улучшениями; гонка с победой/проигрышем и уровнями; градостроитель с ресурсами и развитием.

**Не проходят** (нет механик): лента анекдотов с лайками/дизлайками; просмотр и скачивание мемов; «выбор из двух» с процентами, ни на что не влияющий; ТВ-программа и другая справочная информация.

## 2.7 Возрастной рейтинг

**Суть**: содержание соответствует рейтингу, заявленному в черновике. Модерация оценивает совокупно реалистичность мира, персонажей, оружия и механики насилия; **ключевой фактор — реалистичность графики и подачи**.

Сводка:

| Категория | Эротика | Насилие | Алкоголь и табак | Лексика |
|---|---|---|---|---|
| **0+** | Любая нагота запрещена, включая короткую/обтягивающую одежду, акцент на декольте | Запрещено причинение вреда; запрещены пугающие изображения/звуки (взрывы, скримеры) | Полностью запрещены | Грубая лексика запрещена |
| **6+** | Нейтральная упрощённая/мультяшная нагота без сексуальности | Комическое насилие без вреда; противники исчезают без следов | Полностью запрещены | Грубая лексика запрещена |
| **12+** | Лёгкая сексуальность без эротизации | Нереалистичное, условная кровь, без ран и смерти «в кадре» | Только по сеттингу, без популяризации | Смягчённая; без сексуальных ругательств |
| **16+** | Откровенная сексуальность без вульгарности | Реалистичное, красная кровь, раны без внутренностей | Как предмет/атрибут, без употребления | Грубый юмор и брань допустимы |
| **18+** | Сексуализированная реалистичная нагота | Натуралистичное, расчленение, внутренности | Пропаганда и употребление допустимы | Грубый юмор и брань допустимы |

### 0+

- **Эротика**: запрещена любая графическая нагота, в т.ч. короткая, обтягивающая одежда, акцентированное декольте. Исключения: младенцы/пупсы/куклы в естественной среде (подгузник, нагишом без акцента); мультяшные упрощённые персонажи как есть (спортсмены).
- **Насилие**: запрещено изображение причинения вреда персонажам и живым существам; запрещены изображения/звуки, пугающие маленьких детей (взрывы, скримеры).
- **Алкоголь и табак**: полностью запрещены. **Лексика**: грубая запрещена.
- Примеры: переодевалка с персонажем в полотенце; комичный пловец; персонаж в подгузнике.

### 6+

Игра 0+, в которой есть пугающие сцены или звуки.

- **Эротика**: нейтральное реалистичное/упрощённое/комичное изображение обнажённого тела без сексуальной подоплёки и акцента на поле. Допустимы: одежда, открывающая плечи, руки, колени, живот, мужскую грудь — без крупных планов интимных частей; статуи и барельефы с открытым торсом (без гениталий и женских сосков).
- **Насилие**: комическое («Ну, погоди!», «Том и Джерри») без вреда мультперсонажам; персонажи полностью выдуманные; насилие подразумевается, но не визуализируется (противники исчезают искрами, пузырьками, промаргиванием); нереалистичная графика; аварии и взрывы без визуализации/описания смерти.
- **Алкоголь и табак**: запрещены. **Лексика**: грубая запрещена.
- Примеры: антропоморфная акула в кроссовках; мультяшный торс; платье с разрезом без сексуализации; античная статуя; гонки, где попадание — мерцание противника.

### 12+

- **Эротика**: лёгкая сексуальность и условный акцент на поле без эротизации. Допустимы небольшое декольте, открытые плечи, оголённый живот, короткие шорты/юбки без акцентирующей подачи и фокуса на интимных зонах; в игре нет сексуального контекста.
- **Насилие** — обязательные ограничения:
  - Персонажи полностью вымышленные; насилие над нереалистично прорисованными людьми, животными, фантастическими существами.
  - Графика нереалистична (стилизация, мультяшность, регдолл на схематичных персонажах вроде стикменов).
  - Механика вреда неправдоподобна: нет крови, реалистичных ранений, порезов, страданий, внутренностей, процесса умирания.
  - Кровь только условная (короткие вспышки, цветные брызги, не похожие на кровь). Запрещены лужи, следы на телах/поверхностях/одежде.
  - Смерть — исчезновение, растворение, отключение без следов.
  - Оружие фантазийное или сильно стилизованное, без прямых реальных аналогов.
  - Болезни, аварии, несчастные случаи, ненасильственная смерть — ненатуралистично.
  - Более реалистичное насилие допустимо при одном из условий: **осуждение агрессии** (злодеи получают по заслугам, игрок не поощряется за беспричинную агрессию) или **защита и правопорядок** (самооборона, защита других, обезвреживание злодеев — супергерой, полицейский).
- **Алкоголь и табак**: демонстрация курения/парения/распития, если обусловлено сеттингом, без популяризации и позитивного облика; не центральный элемент геймплея. Объекты с неоднозначной трактовкой, если контекст прямо не указывает на алкоголь (бутылка без маркировки; «Дьявольский коктейль, 36 маг. урона» у «охочего до горячительного пирата» — алкоголь прямо не назван).
- **Лексика**: вся ненормативная лексика смягчена; ругательства, связанные с сексом, недопустимы.
- Примеры: девушки в обтягивающей одежде в фэнтези без эротизации; мультяшные враги исчезают в облачке дыма; огненный меч против монстров; меню ресторана/таверна с алкоголем по сеттингу.

### 16+

- **Эротика**: реалистичное тело с более откровенной сексуальностью без вульгарной эротизации. Допустимы: глубокое декольте, обтягивающая одежда, мини, вырезы, откровенные купальники (бикини минимального покрытия); фокус на груди, ягодицах; лёгкие эротизированные позы (прогиб спины, акцент на бёдрах, талии); просвечивающая фактура сосков — **только внутри игры, на промо запрещено (8.3.5)**.
- **Насилие**: реалистичная графика и механика; красная кровь — брызги, умеренные следы на одежде и поверхностях; видимые ранения без внутренностей; смерть и лежащие тела как факт, без шокирующих подробностей; реалистичные сцены без выраженной жестокости.
- **Алкоголь и табак**: упоминание и изображение как предмета/атрибута — бутылка ликёра, пачка сигарет, незажжённая сигарета, бокал вина на столе; действие «Стрельнуть сигарету» без показа курения.
- **Лексика**: грубый юмор и бранные слова допустимы.

### 18+

- **Эротика**: сексуализированная реалистичная нагота с активной сексуальной подоплёкой. Допустимы: очень глубокое декольте, нижнее бельё, стринги, чулки, пояса; акцент на интимных зонах, гипертрофированные формы; явно сексуальные позы; атрибуты (спальня, душ, клубная подсветка, неон); эротичные анимации и тряска; многозначная мимика. **Только внутри игры, на промо запрещено (8.3.5).**
- **Насилие**: натуралистичное и шокирующее — расчленение, вскрытые органы, открытые переломы, отрубания, обезглавливания; максимально натуралистичная графика; правдоподобная механика и визуализация смерти; обильная кровь (лужи, брызги на камеру, «мясные» фрагменты, внутренности); тела с шокирующими подробностями. **Запрещено по отношению к животным, детям, пожилым людям.** На промо запрещено (8.3.6).
- **Алкоголь и табак**: пропаганда, популяризация, позитивный облик и призывы («с алкоголем вы станете сильнее», «настоящие мужчины курят»); симуляторы употребления; алкоголь/табак как центральный элемент геймплея.
- **Лексика**: грубый юмор и брань допустимы.
- **Другое**: казино, покер и азартные игры — при отсутствии вывода реальных денег/призов (пункт 3.7); отсылки к проституции, бродяжничеству, попрошайничеству; эзотерика как сеттинг (ведьмы, тарологи, ритуалы). **Чёрная магия запрещена**, как и **любые инап-покупки в играх с гаданиями** (пункт 3.4.2).

## 2.9 Длительность контента

**Суть**: прохождение основного содержания занимает **более 10 минут**, или есть мотивация перепроходить.

| | Много контента | Мало контента |
|---|---|---|
| **Есть реиграбельность** | Допускается | Допускается |
| **Нет реиграбельности** | Допускается | **Не допускается** |

**Много основного контента** (подходит для игр, где контент сложно использовать повторно):

- Казуальные игры с 10–20 уровнями.
- Викторины: несколько тем по 15–20 вопросов, **всего не менее 100 вопросов**; вопросы не должны дублироваться или быть минимально изменёнными (другие варианты ответа / переформулировка того же вопроса).
- Головоломки с несколькими уникальными задачами.
- Сюжетные игры (визуальная новелла, чтение которой > 10 минут).

**Реиграбельность** (если прохождение короткое):

- Вариативность: разные варианты ответа в новелле, случайные стартовые условия в стратегии, процедурная генерация уровней в платформере/головоломке, перемешивание карточек в «Найди пару».
- Метаигра: достижения, рекорды, прокачка между забегами. 2048 — условно бесконечна, есть мотивация улучшить результат.

**Отказы**: единственный уровень проходится за 10 секунд; 10 уровней головоломки за три минуты без вариативности; три одинаковые машины и одна трасса без рекордов и соперников; один уровень шутера на 5 минут без мотивации повторить.

## 2.14 Автоопределение языка

**Суть**: язык определяется автоматически через SDK. Обязательно для **всех** игр — даже с одним заявленным языком или без текстов. Определение должно происходить **на старте**, а не в процессе игры.

```javascript
const ysdk = await YaGames.init();
const lang = ysdk.environment.i18n.lang; // 'en', 'ru', ...
```

Код языка — ISO 639-1 (например, `"tr"` — игра запущена в турецком интерфейсе Яндекс Игр). Переменную `lang` использовать при загрузке переводов. Если язык пользователя не поддержан в игре — ориентироваться на резервный набор языков из документации languages-and-domains (раздел languages), а не на дефолт движка.

**Проверка одного языка**: очистить кеш → открыть с debug-панелью → при первом запуске индикатор 文 должен стать зелёным (`I18N is used`) **на старте**. Красный (`I18N is not used`) — не подключено. Допустим небольшой интервал подгрузки: до смены цвета может мелькнуть загрузочный текст на другом языке.

- 🚫 Индикатор становится зелёным только после нажатия «Играть» / запуска уровня — отказ.
- ✅ Небольшая задержка, язык изначально правильный (игра только RU).
- ✅ Надпись «Загружаемся» меняется на «Loading» одновременно со сменой индикатора (язык EN).

**Проверка нескольких языков**: для каждого языка из поля **Игра переведена на** в черновике: **SDK mocks** ⚒️ → выпадающий список языков (напр. **En**) → игра открывается на этом языке в новой вкладке. Вердикты:

- ✅ Все заявленные языки подтянулись.
- 🚫 Хотя бы один язык не переключился (полностью или частично) — отказ за неперевод (с учётом исключений из калибровочного списка 8.2.3).
- ✅ После обновления страницы автоопределение отсутствует, если разработчик сохраняет выбранный язык в кеше (ручной выбор языка приоритетнее — модерация проверит его только на технические/логические ошибки; рекомендации — пункт 6.9).

## 3.6 Дубликаты игр

**Суть**: игра не копирует полностью или частично другую игру из каталога и не дублирует ваши игры. Продолжение публикуется отдельно только при полной переработке сеттинга и/или механик; иначе — обновить предыдущую игру новым контентом. Признание дубликатом: не пройдёт модерацию, не допускается к дальнейшим проверкам, снимается с публикации.

**Название должно быть уникальным в рамках каталога** — иначе дубликат независимо от содержания.

### Четыре параметра оценки

| Параметр | Вопрос | Что учитывается |
|---|---|---|
| **Core-механика** | «Как играть?» | То, что игрок делает чаще всего. Смена только механики при полной идентичности остального — недостаточно, если механики сами по себе не создают нового опыта (кликер, пазлы, слияние падающих, чат, тест). Второстепенные механики: если значительно влияют на опыт — относятся к контенту; если незначительно — не рассматриваются. Примеры: платформеры, шутеры, пазлы, карточные, стелс, симуляторы. |
| **Контент** | «Что тут есть? С чем взаимодействую?» | Сюжет и лор; персонажи и способности; локации, уровни, поле; игровые элементы (фишки, предметы слияния, карты); мета-геймплей (развитие города, получение персонажей/оружия, боевые пропуска); механики удержания (ежедневные задания, лиги, временные активности). Для новых частей — насколько различается контент и достаточен ли его объём. |
| **Дизайн** | «Как выглядит?» | Стилистика (реализм, мультяшность, пиксель-арт); техника и детализация (2D/3D, ручные текстуры/фотореализм); палитра и атмосфера. **Смена фона уровня — недостаточно.** Примеры: Cuphead, Journey, Limbo, Borderlands, Genshin Impact. |
| **UI и UX** | «Что и как игрок видит и нажимает?» | Оформление окон и кнопок, способы управления, вспомогательные инструменты, переходы; меню, инвентарь, здоровье, счёт, таймер, подсказки, курсор, карта, журнал, иконки, загрузочные экраны. |

### Принцип модерирования

🔴 — параметр совпадает, 🟢 — достаточно различается.

| Механика | Контент | Дизайн | UI/UX | Вердикт |
|---|---|---|---|---|
| 🔴 | 🔴 | 🔴 | 🔴 | Дубль |
| 🔴 | 🔴 | 🔴 | 🟢 | Дубль |
| 🔴 | 🔴 | 🟢 | 🔴 | Дубль |
| 🔴 | 🔴 | 🟢 | 🟢 | Дубль |
| 🔴 | 🟢 | 🔴 | 🔴 | Не дубль |
| 🔴 | 🟢 | 🔴 | 🟢 | Не дубль |
| 🔴 | 🟢 | 🟢 | 🔴 | Не дубль |
| 🔴 | 🟢 | 🟢 | 🟢 | Не дубль |
| 🟢 | 🔴 | 🔴 | 🔴 | Дубль |
| 🟢 | 🔴 | 🔴 | 🟢 | Дубль |
| 🟢 | 🔴 | 🟢 | 🔴 | Дубль |
| 🟢 | 🟢 | 🔴 | 🔴 | Не дубль |
| 🟢 | 🟢 | 🔴 | 🟢 | Не дубль |
| 🟢 | 🟢 | 🟢 | 🔴 | Не дубль |
| 🟢 | 🟢 | 🟢 | 🟢 | Не дубль |

**Вывод**: решающий параметр — **контент**. Если контент качественно не различается — дубликат, даже при другой механике (Косынка vs Паук с тем же контентом/дизайном/UI — дубль) или другом UI. Если контент значительно переработан — не дубль, даже при той же механике, дизайне и UI (ритм-игра с другими персонажами, локациями, сюжетом, уровнями — не дубль).

**Не считается новым контентом**: рескин персонажей/мишеней/фишек, смена фона, новые уровни той же структуры, слегка переработанный город из тех же ассетов, перекраска UI.

**Считается новым контентом**: новый лор и локации; новые игровые элементы (оружие, предметы, постройки, бонусы); новые способности персонажей; другие правила (баскетбол vs волейбол; бросок мечей с бегущими персонажами vs бросок топоров со статичными).

## 4.4 Расположение рекламы

**Суть**: реклама не мешает взаимодействовать с игрой и показывается только в логических паузах. Показ предсказуем, не отнимает лишнее время. Если куплено отключение рекламы — после покупки реклама не показывается.

Частота показа полноэкранной рекламы управляется платформой; при слишком частом вызове в консоли браузера появится предупреждение.

### Вне игрового процесса (любые игры)

Рекламу можно показывать:

- **После запуска игры** на платформе — то есть **после срабатывания Game Ready** (`LoadingAPI.ready()`), не до него.
- При **неигровом действии** — действия в меню, настройках, дополнительных экранах, не связанные с основным геймплеем: выбор уровня, кнопки **Новый уровень**, **Следующая**, **Начать заново**, **Снова**, **Магазин**, **Ваша коллекция**, **Выйти**.

Механика: дождаться неигрового действия → **сразу** показать рекламу (пользователь закроет её сам) → продолжить (запустить уровень, открыть магазин). Максимальная задержка между действием и началом рекламы — **2 секунды**. Предупреждение в этом случае не нужно.

### В процессе игры

| | Уровни короче 5 минут* | Уровни длиннее 5 минут* |
|---|---|---|
| **Условно-пошаговые игры** | После игровых действий | После игровых действий |
| **Игры в реальном времени** | Внутри уровня **недопустимо** | По таймеру |

\* Успешное прохождение уровня без проигрышей среднестатистическим взрослым.

**Условно-пошаговые** (пользователь совершает действие и ждёт реакции: тесты, викторины, пазлы, любые механики слияния/merge, детективные головоломки, 2048-подобные): показывать рекламу **сразу после действия пользователя, без предупреждения**, задержка ≤ 2 с. Примеры: после последнего кусочка пазла; после выбора ответа; после броска кубика в merge.

**Игры в реальном времени**:

- Короткие уровни (< 5 мин) — внутри уровня реклама недопустима; только после неигрового действия.
- Длинные уровни (> 5 мин) — реклама по таймеру в любой момент, но **игра ставится на паузу** и игрок **предупреждается таймером**: крупная плашка «Реклама через 2, 1», после неё реклама.

**Предупреждения о рекламе** должны:

- Быть заметными и легко читаться (и переведены на язык игры — 8.2.3; не обрезаться — 1.10).
- Длиться **2 секунды** (затянутые паузы отбивают желание играть).
- Быть не избыточными: одно предупреждение перед одним показом.

Во время предупреждения и самой рекламы **взаимодействие с игрой на паузе** (анимацию можно не замораживать, но игровые действия заблокированы). Иначе — случайные клики по рекламе, отказы у рекламодателей, меньший доход.

### Диалоговые окна

| | Модальное окно | Немодальное окно |
|---|---|---|
| **Условно-пошаговые** | После пользовательского действия | После пользовательского действия |
| **В реальном времени** | После пользовательского действия | По таймеру, если уровни длиннее 5 минут |

**Модальное окно** блокирует геймплей, пока не закрыто (обучение, календарь, скины, «Уровень пройден»). Допустимы анимация и звуки под окном, кликабельность неигровых кнопок (**Меню**, **Настройки**), окно поверх окна. Реклама:

- Окно открыто по действию пользователя → правила «вне игрового процесса» с момента вызова окна (реклама сразу по клику, например по **Выйти** в викторине).
- Окно открыто без действия (персонаж дошёл до точки, уведомление о прогрессе) → его появление — часть геймплея; операции внутри окна, включая закрытие или «Забрать × 50», — уже вне игры, реклама после них допустима.

**Немодальное окно** не блокирует геймплей (можно управлять персонажем при открытом окне фона/скинов, боковой магазин в кликере, «Получить бустер» у предмета). Реклама — по правилам «в процессе игры»: для длинных игр реального времени — по таймеру с предупреждением и паузой (предупреждение поверх немодального окна допустимо). **Некорректно**: реальное время, у двери появляется немодальное «Уверены, что хотите зайти?» → реклама по клику «Да!» — правильно показать по таймеру.

### Задержка перед рекламой

Лимит — **2 секунды** от действия (момент, когда кнопка реагирует на клик — меняет цвет/размер) до начала показа. Модерация проверяет на привычном устройстве, в инкогнито и на другом устройстве; если хотя бы раз задержки нет — требование выполнено. Стабильную задержку замеряют по видеозаписи (например, в VLC). Нарушение — только явная задержка **больше 2 с** (пример отказа — 2,5 с); пограничные случаи проходят.

### Тестирование рекламы

Через prod-окружение (local-launch, prod-env) или в режиме черновика (draft-mode) — в обоих случаях показывается настоящая реклама реальной платформы.

## 5.1.1.2 Демонстрация геймплея, механики и графики

**Суть**: скриншоты демонстрируют реальный геймплей, занимающий **не менее 70%** изображения; остальное — обрамление или эффекты. Исключение: материалы, качественно демонстрирующие основную механику и графику.

**Расчёт**: площадь изображения (ширина × высота) и площадь прямоугольного фрагмента с геймплеем; доля = фрагмент / изображение × 100%. Пример: 1270×720 = 914 400 px; фрагмент 865×455 = 393 575 px → ≈ 43%.

**Качественная демонстрация** (проходит даже при < 70%): свободное место заполнено поясняющим текстом, игровыми объектами, персонажами, визуальными эффектами. Примеры: 43% геймплея + лесной фон + портрет персонажа + «Героические сражения»; игровые объекты на фоне + «Получай классные награды!» (геймплея нет вообще); триптих стилизованного геймплея > 70%.

**Нарушение**: **более 30%** занято однотонным фоном, градиентом или не относящимся к игре. Примеры отказа: интерфейс судоку в центре бежевого фона (≈ 32%); игра в слова на голубом фоне (≈ 40%).

## 5.1.3 Одинаковое название игры

**Суть**: название для каждого языка черновика **абсолютно идентично** в самой игре, во всех текстовых полях (название, «Об игре», SEO-описание, «Как играть») и на всех промоматериалах (обложки, иконки, скриншоты, баннеры, видео).

**Названия считаются разными, если**:

- Использованы разные слова (включая артикли).
- В одном отсутствуют некоторые выражения.
- Другой порядок слов.
- Написаны на разных языках или не на языке локализации черновика.
- Различается написание слов.
- Расстановка пробелов меняет смысл.

Примеры отказа:

| Название в черновике | Где иначе | Проблема |
|---|---|---|
| «Кубикрафт: Слияние Кубов 2048» | Обложка: только «2048» крупно | Читается как самостоятельное название |
| «Хакер Кликер» | Обложка: «Hacker Clicker» | Разные языки |
| «Bag Design 3D» | Обложка: «BAG SHOP» | Другая часть/слово |
| «Квест "Лабиринт страха"» | Обложка: «ЛАБИРИНТ СТРАХА» | Пропущено слово «Квест» |
| «Sweet sugar» | Обложка: + бирка «candy», соединённая линией | Образовано другое название |
| «Тест FNaF Да или Нет» | Обложка: «FNAF ТЕСТ ДА ИЛИ НЕТ» | Порядок слов изменён без стилизации |
| «Rusichi vs Lizards» | Об игре: «Russians vs Lizards» | Другое слово |
| «Мастер цвета» | SEO: «Мастер цвет» | На букву короче |
| «A popular drawing game» | Обложка: без артикля «a» | Пропущен артикль |
| «CountrySurfers» | SEO: «Countr ySurfers» | Пробел не на месте, смысл изменён |

**Допустимо**:

- На креативе только часть названия, если она не воспринимается как другая версия названия (читается как жанр/тег: «судоку» в описании «Знаток судоку»).
- Упоминание жанра и ключевых особенностей («3D» на иконке «LowPoly 3D Art»).
- Сторонние надписи — внутриигровые материалы или возможности (пример вопроса на обложке; «БОЛЕЕ 60 ТЕСТОВ»; бутылки «Лалтика» в антураже).
- Креативное расположение частей названия, если оно выглядит идентичным («ПОКЕР» крупно на фишке, «ЛАС-ВЕГАС» по краю).
- Логотип разработчика с названием студии.
- Произвольный текст без части названия: призыв или лозунг («КЛИКАЙ И ЭВОЛЮЦИОНИРУЙ»).

Допустимые различия в написании:

- Замена 1–2 букв картинками при сохранении читаемости («МОНЕТОЧКА» с монетой вместо «О»).
- Разный регистр («КАМИСАДО ОНЛАЙН»; «Слово пацана» vs «СЛОВО ПАЦАНА»).
- Разные знаки пунктуации (без двоеточия).
- Разные падежи («мир Энергониума»).
- «&» ↔ «and» («Hook & Lava» / «Hook and Lava»).
- Римские ↔ арабские цифры («GTA 6» / «GTA VI»).
- Добавление/удаление переноса строки («Buzz / Words»).
- Добавление/удаление пробелов, если смысл не меняется («CountrySurfers» / «Country Surfers»).

## 8.2.3 Переводы текстов

**Суть**: тексты, которые меняются от языка и значимы для геймплея, переведены на соответствующий язык. Понятные независимо от языка фразы можно не переводить.

### Нужно переводить

- **Внутриигровая валюта**: «100 Коинов», «КОИНЫ», «баксы», «Монеты», «Туалетная бумага» — на языке игры.
- **Все кнопки и игровые элементы**: «Free» → «Бесплатно» (надпись на кнопке — не дополнение к элементу); «Купить» → «Buy» (в английской версии); «Select level» → «Выберите уровень»; «Уровень», «Введите имя».
- **Геймплейные тексты** (влияют на понимание происходящего): «Exit» → «Выход»; «Score», «Best» → «Счёт», «Рекорд»; «No data» → «Нет данных»; «Day 7» → «День 7»; «Game over» → «Игра окончена»; «20X VALUE / PREMIUM / FREE» как отдельные надписи → «В 20 РАЗ БОЛЬШЕ / ПРЕМИУМ / БЕСПЛАТНО».
- **Предупреждения о рекламе**: «Рекламная пауза, Через 1...» в английской версии → «Advertisement in 1...»; «Пауза» в турецкой → «Duraklat».
- **Описание управления**: «Jump» → «Прыжок»; «Press E to Continue» → «Нажмите E, чтобы продолжить»; «Click to start» → «Нажмите, чтобы начать».
- **Двойной перевод недопустим**: текст одновременно на двух языках — нарушение. «Select language / Выберите язык» → только «Выберите язык»; «Next — Продолжить» → «Продолжить»; «Bubble / Пузырёк» → «Пузырёк»; «англ eng» → «англ».
- **Название текущего языка** — на этом же языке: «Russian (ru)» → «Русский».

### Не нужно переводить

- **Сокращения и аббревиатуры** в любом регистре: ad, ADS, OK, VIP, lvl, Lv, adv, min, max, MAX, Kb, Mb, Mph, Kbps, Mbps, стороны света (W, N), am/pm («4 am»), «v.» для версии.
- **Названия клавиш**: Ctrl, Alt, Shift, TAB, R, F, E, T, «Левый Shift». **Пробел/Space** переводить необязательно; название клавиши можно опустить при узнаваемом изображении.
- **Имена собственные без официального перевода**: ники игроков (в т.ч. системные «Player 573577», «Player73ab810»), торговые марки, названия приложений/программ/компаний (Tumblr, Telegram, Photoshop, DNS, AliExpress, NETFLIX), языки программирования (C#, Python, Java), названия оружия (TEC9 "Fable", M4 "Samurai"), имена персонажей (Lava).
- **Окружение** — тексты, с которыми игрок не взаимодействует и которые не важны для геймплея: логотипы, слоганы, названия движков («powered by unity»), вывески («Jewellery», «Motel», «Reception»), надписи на зданиях («Kill the enemies» на плакате), названия песен, оригинальные твиты, «Free case» на картинке кейса, «Score/Time/Rings» на скриншоте другой игры внутри викторины, «Lotus» на логотипе в вопросе.
- **Эффекты окружения** — временные визуальные эффекты и комикс-звуки: «pain», «crack», «ouch!», «oh!», «combo», «great!», «Not bad», «Boom!».
- **Символы без перевода**: @, &, операторы языков программирования (and, or, xor, not, cycle), математические функции (log, ln, exp, mod), химические элементы (Ag), аккорды (A, B, C, D, E, F, G).
- **Названия языков** в окне выбора — каждый на своём языке: Русский, English, Deutsch, Türkçe, Беларуская, Español.
- **Дополнения к элементам интерфейса** — общеизвестные слова, вшитые в UI-элементы: NEW, SALE, FREE («FREE» мелко под «Завершить»; «10% Sale» на товаре; «OFF 1» на переключателе; «Rare»/«Epic» на подложках карточек на промо). Исключение — если это **отдельные надписи** (см. «20X VALUE / PREMIUM / FREE» выше).
- **Названия жанров**: RPG, idle, action, clicker, «idle-RPG».
- **Коды реальных валют** (USD, RUB). Название и иконку **портальной** валюты брать из SDK (1.13.2), а не вручную.

## 8.3.4 Элементы интерфейса на медиаматериалах

**Суть**: медиаматериалы (обложки, иконки, скриншоты, баннеры, рекламные видео, тексты описания) **не содержат**:

- Элементов **системного интерфейса**: статус-бар, часы, индикатор батареи, Wi-Fi, интерфейс мобильного браузера, шапка Яндекс Игр (логотип, название, Яны, кнопка полноэкранного режима), **debug-панель**.
- Элементов **интерфейса Яндекс Игр** или их имитации: бейджи («Акция», «Новая игра», «Промо», «Обновление», «Лучшее!»), игровой рейтинг (зелёный/серый квадрат с числом «98», «91», «58»), возрастное ограничение («18+» в углу).

Рейтинги, бейджи и возрастные метки добавляет сама платформа. **Элементы интерфейса игры** (шкала здоровья, таймер, счёт, кнопки, «Золото +50: будет показана реклама») допустимы на скриншотах, но **не на иконках и обложках**.

## 8.3.5 Эротика и дискриминация

**Суть**: медиаматериалы не содержат порнографии и эротики, предметов, имитирующих половые органы, отсылок к половому акту, оскорблений по полу/национальности/религии, а также любых материалов сексуального насилия над детьми (включая созданные/изменённые ИИ или deepfake, даже если не изображают реального несовершеннолетнего).

Требования к контенту **внутри игры мягче**, чем к промо: эротика внутри допустима при отсутствии порнографии, соответствии законодательству всех стран распространения и возрастной отметке; промо при этом не содержит запрещённой эротики.

### Порнография (учитывается и игра, и промо)

Отказ/удаление, если есть:

- **Откровенный контент** (порнография).
- **Призывы к оголению** в текстах, промо или на игровых элементах (название «Сотри одежду», кнопка «Раздеть девушку» на экране победы, rewarded-кнопка с призывом).
- **Механика раздевания**, не обусловленная жанром (стирание одежды мышью). Допустимы игры про подбор одежды, где смена нарядов — часть процесса.

### Эротика на промоматериалах — принцип

| Медиа \ Текст | Откровенный эротический текст | Текст с намёком | Приемлемый текст |
|---|---|---|---|
| **Откровенные эротические медиа** | Отказ | Отказ | Отказ |
| **Медиа с намёком** | Отказ | Отказ (намёк более чем в одном материале) | Допуск (намёк только в одном материале) |
| **Приемлемые медиа** | Отказ | Допуск (намёк только в одном материале) | Допуск |

**Запрещённая эротика** (отказ/удаление):

- Основной эротический посыл материалов.
- Эротическая обстановка: силуэты антропоморфных персонажей или интимных частей тела на фоне кровати, сцены свидания.
- Откровенная эротика: отсылки к сексу; **цензура** (смайлики, чёрные круги, круги «18+»); сексуализированные раздевание/нагота; фокус на преувеличенно сексуализированных персонажах; имитация половых органов или молочных желёз и их силуэты.
- Эротический кликбейт: эротические иконка/промо при неэротическом содержании (девушка в белье на обложке теста по советским фильмам).
- Эротика в текстовых блоках: слова в названии/описании эксплуатируют интерес к сексу («Раздень тянку», «Сорви и Посмотри Под», «Сочные аниме девочки», «Разные спальни!», «Расслабься, разглядывая», «Проведи вечер… раскрой свои фантазии» с изображением девочки-подростка).

Примеры отказа: торс девушки в расстёгнутой рубашке на обложке гонок; фокус на стопах (фут-фетиш); чёрные круги + «Раздень тянку / Кликай»; мокрый обнажённый по пояс парень в бассейне; силуэт полового органа; силуэт девушки с гиперболизированными формами в спальне; гиперболизированная грудь крупным планом.

**Допустимый контент** (сексуализированные образы без прямой эксплуатации интереса к сексу — мультяшные персонажи или образы, обусловленные жанром):

- Доска для сёрфинга прикрывает девушку (не цензура), текст нейтрален.
- Девушка в школьной форме, текст про клики и валюту.
- Текст «сними с девушки лишнюю одежду», но девушка в пальто и сапогах на пляже.
- Силуэт одетой девушки — зависит от контекста (одевалка — ок, раздевание — отказ).
- Одевалка «Гламур #ПляжнаяЖизнь» с девушками в топах — обусловлено жанром.
- Описание «красоту женского тела», но нейтральная обложка.
- Румянец и обтягивающая блуза, но описание только про романтику.
- Для стратегий и RPG допустимы фэнтезийные сексуализированные образы, если игра не сосредоточена на эротике (девушка в кожаных штанах и противогазе с фальшфейером почти в полный рост).

**Приемлемый контент**: не связан с сексом; эротики нет или её элементы обусловлены тематикой; контекст нейтрален. Силуэты мультперсонажей, предметов, людей допустимы (силуэт Пикачу — не цензура). В одевалке допустимы персонажи в нижнем белье, если это не откровенная запрещённая эротика. Примеры: богатырь с открытым торсом без сосков; приложение тренировок ягодиц с до/после; накачанный персонаж в шортах про допинг; тверк-раннер с карикатурными формами; девушка в закрытом платье у трассы, не главный элемент; погрудный портрет в купальнике без акцента на декольте для симулятора пляжа.

## 8.3.6 Неприятный и шокирующий контент

**Суть**: медиаматериалы безопасны, этичны и пригодны для всех возрастов. Иначе сервис может не показывать игру на главной, в разделах и подборках или не допустить к публикации. Промо не должны быть сосредоточены на: туалетном контенте; страшных персонажах и сеттинге; обилии крови. Внутри игры такой контент допустим при соблюдении правил, законодательства и возрастной отметке.

### Туалетный контент

К теме относятся: продукты жизнедеятельности (фекалии, использованные подгузники); мочеиспускание и дефекация; туалетные атрибуты; скибиди-туалеты (унитазы с человеческими головами); неприятные слова («какашка», «пук» и похожие).

**Отказ**, если на промо:

- Основная тема — фекалии, даже схематичные («Побег Какашки!», merge-игра с какашками, «Весёлая Какашка Кликер»).
- Процессы жизнедеятельности в фокусе («Симулятор Туалета», «Пукающая птица» со следом газа, «Братья Пук»).
- Основной контент — туалетный, независимо от правдоподобности (скибиди-туалет на экране телефона, шутер по унитазам, слияние туалетных монстров, раскраска со скибиди на обложке).
- Неприятный контент в текстах («Какой Ты ФЕКАЛИЙ?», «Мой туалет» с кормлением туалета, «Головой в какашку», «Пуки — Весёлые звуки»).

**Допуск**: тема присутствует на фоне, не в фокусе, атрибуты не правдоподобны: эмодзи-какашка среди других эмодзи; коричневые пятна на ковре в симуляторе чистки; скибиди-туалет мелькает среди мемов в merge; мультяшный грязный унитаз в ванной, которую нужно убрать; унитаз как антураж дома мечты; рулоны туалетной бумаги в кладовке.

### Неприятные персонажи и сеттинги

Нежелательный контент: маргинальные/криминальные группы (гопники), субкультуры, бездомные; уродства и болезни; скелеты, тела людей/животных; мутации, зомби, монстры, искажённые существа (Сиреноголовый, Чумной доктор, Мо-Мо, голова скибиди, Мудрый Дуб — степень зависит от графики); сеттинги: похоронные бюро, морги, пыточные, вскрытия, анатомический театр, симулятор создания животных.

| Неприятный контент | В фокусе | Не в фокусе |
|---|---|---|
| **Вызывает сильные отвращение или страх** | Запрещён в любом виде | Запрещён в любом виде |
| **Реалистичный** | Отказ (исключение: реалистичные скелеты людей/животных в фэнтези, если они неотъемлемая часть жанра) | Допуск — правдоподобно, но не бросается в глаза |
| **Упрощённый** | Допуск — схематично, нестрашно, дружелюбно | Допуск |

**В фокусе** — фигуры, которые первыми бросаются в глаза: контрастный персонаж даже на втором плане; затемнённый или размытый персонаж на первом плане — **не** в фокусе.

Примеры отказа: реалистичные бомж и гопник крупным планом; персонаж с тюремными наколками + описание «вырубает с вертухи»; ступня с порезами и абсцессами; окровавленная голова свиньи; реалистичный череп с венами; труп на столе для вскрытия; Момо; гибрид-мутант с кровью; некстботы с деформированными лицами; реалистичные скелеты-зомби на переднем плане; маленькие окровавленные зомби как единственный элемент обложки; реалистичное кладбище с гробом; палата с трупом и кровью; анатомическая иконка собаки (мышцы, органы, скелет).

Примеры допуска: карикатурные гопники («Доценты»); мультяшный грабитель-стикмен; Чумной доктор как историческая фигура; реалистичная лисья маска; схематичные зомби Plants vs. Zombies; милые монстры; скелеты Warhammer 40000 (сеттинг); Терминатор (жанр); реалистичные зомби в расфокусе, сливающиеся с фоном; окровавленный монстр при очень низкой контрастности; пришельцы в тёмной форме, не бросающиеся в глаза; размытые зомби на горизонте; череп и пауки в террариуме на фоне; схематичный морг без тел и крови; чёрно-белая фотография заброшки без неприятного контента.

### Визуализация крови

Отказ, если промо сосредоточены на крови (даже схематичной), тяжёлых травмах, оторванных конечностях, кровотечениях и жестокости (открытые переломы, пытки). Типичные жанры-нарушители: военные шутеры с реалистичным сеттингом; реалистичные шутеры с антропоморфными зомби; хорроры про расчленение; песочницы с «тряпичными куклами», где травмы в фокусе.

Примеры отказа — реалистичные: изувеченные останки без головы и ноги в лужах крови; монахиня с окровавленными зубами и молотком среди брызг; козёл с фонтаном крови из горла. Упрощённые, но тоже отказ: схематичные трупы и пол в крови; «Mr.Meat» с лужей крови на большей части экрана; Melon Sandbox с фонтанами крови из зомби; лучники со стрелой в колене и кровью изо рта; стикмены с отлетающей головой и брызгами (ragdoll для травмирования).

Допуск — мультяшная кровь (пиксельные всплески, спрайты, цветная кровь из роботов/кукол), обложка не сосредоточена на ней: олень с дротиком и однотонным красным пятном; схематичный выстрел с многоугольником крови из спины; белая фигурка с каплями; красные/голубые кляксы при столкновении толп.

## 8.4.1 Ссылки на другие игры

**Суть**: ссылки в текстах и медиаматериалах встроены через SDK (sdk-other-games) и ведут на **ваши** игры в каталоге Яндекс Игр. Переход не прерывает геймплей, элементы навигации (разделы «More Games», ссылки, кнопки) очевидны.

Критерии:

- Ссылки встроены через SDK и ведут на ваши игры в каталоге.
- По элементам навигации понятно, куда они ведут.
- Переход к другим играм только **вне активного геймплея** (меню, между уровнями).
- При переходе текущая вкладка с игрой **не закрывается**.

На ТВ ссылки на другие игры разработчика запрещены (1.6.3).

**Проверка**: очистить кеш → открыть с debug-панелью → **SDK mocks** ⚒️ → 🔗 **Game links mock is enabled** → подождать 5 секунд → перезагрузить → перейти по ссылке на другую игру. Если API используется правильно, откроется статическая страница `https://app-XXXX.games.s3.yandex.net/helpers/fake-page` с текстом «Hi». Если открылась другая страница (например, каталог или реальная игра) — ссылки добавлены неправильно (прямой `<a href>`/`window.open` на URL каталога вместо SDK).
